从今年三月开始，我会用半年时间，循序渐进地记录一条 AI Agent 的学习路径。这是系列第一篇：先把"Agent 到底是什么"讲清楚。

## 从聊天到行动

过去我们用大模型，主要是"问答"：问一句，模型答一句。信息是单向流动的，模型再聪明，也只是一个知识库加文本生成器。

Agent（智能体）的关键变化在于：**它不只是回答问题，而是为了完成一个目标，自主地调用工具、获取反馈、迭代行动**。同样是"帮我订一张去上海的机票"，聊天机器人会告诉你订票步骤，Agent 则会去查航班、比价格、调用订票接口、最后把订单信息给你确认。

## 一个 Agent 的四个核心要素

业界对 Agent 的拆解大同小异，我习惯记住这个框架：

| 要素 | 作用 | 通俗理解 |
| --- | --- | --- |
| 大脑（LLM） | 理解指令、推理决策 | 思考能力 |
| 规划（Planning） | 把目标拆成步骤、反思纠错 | 做事条理 |
| 记忆（Memory） | 保存上下文与长期知识 | 记性 |
| 工具（Tools） | 调用外部 API、代码、搜索等 | 手脚 |

这四个要素缺一不可。只有大脑没有手脚，就退化成聊天机器人；只有工具没有规划，就只是一堆零散的 API。

## Agent 是怎么"工作"的

几乎所有 Agent 都遵循同一个底层循环：

1. 接收一个目标（用户指令）
2. 大脑根据当前状态推理：下一步该做什么
3. 决定调用某个工具（或不调用）
4. 拿到工具返回的结果，更新记忆
5. 回到第 2 步，直到目标完成或主动停止

这个"思考-行动-观察"的循环在学术界有个经典名字叫 ReAct，后面四月我会专门写一篇手把手实现它的文章，今天先记住这个感觉。

## 为什么要现在学 Agent

大模型本身是"单轮能力"，Agent 才是把能力变成生产力的产品形态。无论是写代码、做分析、管日程，还是本博客后续要做的各种小应用，底层都是这一套循环。理解了 Agent，就等于理解了 2026 年 AI 应用的通用骨架。
