上篇的 ReAct 循环有个明显短板：模型每次调用都"重新开始"，只有当前对话里塞进去的内容才是它的记忆。这一课我们把"记性"做出来。

## 先分清三种记忆

| 类型 | 载体 | 特点 | 类比 |
| --- | --- | --- | --- |
| 短期记忆 | 对话上下文 | 本次任务内有效，占 Token | 工作记忆 |
| 长期记忆 | 外部存储（数据库/文件/向量库） | 跨会话保留，按需取用 | 笔记本 |
| 程序记忆 | 代码、工具、知识库 | 不随对话变化 | 肌肉记忆 |

关键结论：**Agent 没有免费的记忆**。短期记忆挤占上下文窗口，长期记忆需要读写成本。设计的本质是"什么必须随身带，什么可以放仓库、用时再取"。

## 短期记忆管理三板斧

1. **裁剪**：对话超过阈值就删掉最早的无用消息；
2. **摘要**：把一段历史压缩成几句话，替换原文（可分层：每日摘要、每周总结）；
3. **只留最近 N 轮 + 摘要**：很多生产 Agent 就靠这一条规则撑住长对话。

## 长期记忆：从"全量"到"向量检索"

当记忆量大到塞不进上下文时，思路要反过来：**别把所有记忆都给模型，让模型"按需搜索"**。常见做法：

- 把每段记忆切成小块（chunk）；
- 用嵌入模型（embedding）把文本变成向量，存入向量数据库；
- 需要时，把当前问题也转成向量，做相似度检索，取回最相关的若干块，拼进上下文。

这就是 RAG（检索增强生成）在记忆场景的应用，五月会专门展开。

## 极简长期记忆实现

不引入重型向量库，先用"关键词检索"理解全流程：

```python
import json

class SimpleMemory:
    def __init__(self):
        self.notes = []   # 每条: {"text": str, "tags": [str]}

    def remember(self, text: str, tags: list[str] | None = None):
        self.notes.append({"text": text, "tags": tags or []})

    def recall(self, query: str, top_k: int = 3) -> list[str]:
        # 关键词命中打分，取 top_k
        scored = []
        for n in self.notes:
            score = sum(1 for kw in query.split() if kw in n["text"]) \
                    + sum(1 for t in n["tags"] if t in query)
            scored.append((score, n["text"]))
        scored.sort(reverse=True)
        return [t for _, t in scored[:top_k] if _ > 0]
```

在 ReAct 循环里给模型加一个 `remember` 和一个 `search_memory` 工具，Agent 就能"跨轮记住"了：重要的结论主动存，需要时先检索再回答。

## 实践中容易踩的坑

- **存了不检索 = 白存**：记忆要能被工具触达，否则只是死数据；
- **检索不到就编**：模型在记忆里找不到答案时倾向于编造。对策：把检索结果明确标注为"资料"并允许"未找到"；
- **隐私与污染**：长期记忆会累积错误。重要场景要支持"删除/修正某条记忆"，并定期清理。

## 小结

记忆的本质是**上下文管理**：短期靠裁剪与摘要，长期靠外部存储加按需检索。下一篇进入最后一个核心能力——规划，让 Agent 学会把复杂任务拆开做。
