Agent 越自主，越需要一个朴素的问题：**它能不能做不该做的事？** 答案不是"少给权限"或"不信它"，而是设计一套"人在回路（Human-in-the-Loop）"机制：让 Agent 负责跑腿，人类负责把关。

## 三类人工介入点

### 1. 关键行动前：确认（Approve）

把"不可逆或高影响"的动作设为需人工确认：对外发消息、下单支付、删除数据、发布内容。技术实现上，LangGraph 的 `interrupt` 可以暂停流程等待人类输入（五月的实战里提过）；手写循环就在工具执行层加一道闸门：

```python
def guarded_tool(name, args, state):
    if name in NEED_APPROVAL:           # {"send_email", "delete_file", ...}
        decision = ask_human(f"是否执行 {name}({args})？ [y/n]")
        if decision != "y":
            return "用户已取消该操作"
    return execute(name, args)
```

### 2. 过程中：改道与接管（Redirect）

允许人在流程中途插入新指令、纠正方向，而不是只能"全对或全错"。实现上可以给人一个"对话口"：流程每走一步（或关键几步）停下来征询，或提供"暂停并转向"的命令。

### 3. 出问题时：兜底（Fallback）

超出 Agent 能力或置信度不足时，主动升级给人处理，而不是硬答。一个实用技巧是让模型在回答里自带"置信度/是否需要人工"，低于阈值则转人工。

## 安全护栏：不把希望全押在提示词上

只靠 system 提示词约束行为是不够的（它可能被绕过，也可能偶尔失效）。工程护栏更重要：

- **权限最小化**：Agent 只拿到完成任务所需的最小权限，用独立账号、按域授权（例如只能读写某个目录）；
- **动作白名单/黑名单**：代码层硬编码"绝不能做"清单，不依赖模型自觉；
- **输出过滤**：对外发布前过一遍敏感信息与格式校验；
- **限速与配额**：防止循环失控造成无限调用（Token 炸弹）；
- **内容安全**：对外内容与用户输入双向审核，接入内容安全 API。

## 设计哲学：让"人"省力而非"人"沦为监工

人工介入点不是越多越好。每个确认弹窗都是一次打断，过多会让人疲于点按钮，最后麻木地全部点"同意"——机制就失效了。经验法则：

| 介入程度 | 适用场景 |
| --- | --- |
| 全自动 | 低风险、可回滚（整理草稿、检索资料） |
| 例外确认 | 只对高风险动作弹窗（默认放行低风险） |
| 逐步确认 | 中高风险、人需要把控节奏 |
| 全人工 | 不可回滚、合规敏感（对外正式发布） |

**风险高低 = 影响面 × 可逆性**，先按这个公式给每个工具打分，再定它在哪一档。

## 用我们博客的场景收个尾

举一个贯穿后续实战的例子：一个"博客写作 Agent"，它的合理分工是——检索资料、起草、润色全自动；**发布上线必须人工确认**；删除历史文章需要更高权限。这套"自动化跑腿 + 关键处把关"的搭配，就是人在回路最典型的落地形态。

## 小结

Agent 的可靠性 = 模型能力 × 工程护栏 × 人的关键把关。六月的三课（协作、观测、人审）解决的是"多、乱、险"，七月份我们进入生产上线：先学打通工具生态的 MCP 协议，再谈稳定性的工程细节。
