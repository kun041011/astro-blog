2025 年 3 月到 5 月，作为项目负责人，我开发了一套智能情感分析系统。它解决两个问题：传统情感分析粒度太粗（只能判断正负面），而直接让 LLM 分析又存在领域知识不足、输出不稳定。

## 设计思路

- **ABSA 细粒度分析链**：基于 LangChain 构建基于方面级情感分析（Aspect-Based Sentiment Analysis）链路，不满足于"这条评论是好评"，而是抽取到**四元组**——例如"（屏幕，清晰度，正面，很清晰）"，把"谁对什么持什么态度"拆清楚；
- **结构化输出**：用 Pydantic 约束模型输出为 JSON Schema，从源头保证下游可用，而不是依赖正则去"猜"输出；
- **RAG 增强语义检索**：用 FAISS 建向量库做召回，补充领域知识，减少 LLM 幻觉；
- **Agent 路由**：根据问题类型动态调度问答链路，而不是所有请求都走同一条重链路；
- **服务化**：整体封装为 FastAPI 服务，接口化对外提供能力。

## 效果与落地

- 响应时间低于 **200ms**；
- 引入 RAG 召回后，对新评论的分析准确率相比纯 LLM 提升 **22%**；
- 这套中台后续被应用到实习公司的**舆情监控项目**中，支撑日均万级评论的处理。

这个项目让我第一次把"Agent 的组合拳"打在实际业务上：模型负责理解与生成，检索负责补知识，路由负责控成本，Pydantic 负责保证输出质量。也是从这时起，我对 Agent 的工程化产生了浓厚兴趣——那之后我专门用半年时间系统学习了 Agent 体系，并在这里连载了完整的学习系列。
